--- slide 4
Why MCP: one standard plug instead of custom wiring
4
MESA Term 2 | Advanced AI | S4: Plug It In

Without MCP
Every AI app needs its own wiring to every tool.
3 apps x 3 tools = 9 custom connections.
Change a tool and you fix it in three places.
Picture: a different plug for every appliance in the office.

With MCP
Write the tool once as a server.
Any AI app that speaks MCP plugs in.
3 apps + 3 tools = 6 connections, and each is standard.
Picture: a universal socket. The appliance does not care who made the wall.

Dhruva example
get_application could serve the triage agent, Ira's dashboard assistant and an analyst's chat tool. Written once as an MCP server, all three can use it. MCP stands for Model Context Protocol. A protocol is just an agreed set of rules, like a standard form.


i
MCP is a standard socket for tools. Build the tool once, plug it in anywhere.

Three roles: host, client and server
6
MESA Term 2 | Advanced AI | S4: Plug It In
Role | The picture | Dhruva example
Host | The front desk: the AI application the user talks to | Claude Code, or Ira's dashboard assistant
Client | A dedicated phone line from the front desk to one department | Created by the host, one per server
Server | The department that offers services | Our dhruva-triage server, offering get_application and escalate_to_analyst

Same room or a phone call
A server on your own laptop talks through a pipe (stdio): like passing notes in the same room.
A server on another machine talks over the web (HTTP): like a phone call to another office.

Plug in only servers you trust
A server hands your assistant text. Hidden instructions inside that text are called prompt injection: a forged memo slipped into the in-tray.
Your own server is safe. A stranger's is a risk.

A tool call in four steps: ask, choose, call, return
8
MESA Term 2 | Advanced AI | S4: Plug It In
Step | What happens | The picture | The MCP word
1 Ask | The host asks the server: what can you do? | The front desk asks the department for its service list | tools/list
2 Choose | The model reads the list (the job cards) and picks a tool | The consultant picks a slot | (inside the model)
3 Call | The host sends the call to the server, which runs the function | The department's clerk does the job | tools/call
4 Return | The result goes back and the model writes its reply | The answer comes back through the slot | (the result)

Dhruva example
User: 'Tell me about FactoryDesk.' The host lists the tools. The model picks get_application. The server looks up A03 and returns the fields. The model writes the summary.

Read the server before you run it: four questions
11
MESA Term 2 | Advanced AI | S4: Plug It In
# | Question | Where to look | A gap looks like
1 | Is the label (description) good enough for the model to pick this tool? | The docstring under the function | 'Gets an application'
2 | Are the inputs typed, so the server can refuse a wrong one? | The function line, e.g. app_id: str | No type, or a made-up name
3 | Does a jam return a code and what to do next, not nothing? | The return lines | Returns None, or crashes
4 | Does it avoid print()? It talks to the host on one line; a stray print is someone shouting on the line | Search for print( | print( anywhere in the file

The consultant's desk and the filing cabinet
14
MESA Term 2 | Advanced AI | S4: Plug It In
Word | The picture | In plain words
Context | The consultant's desk: only what is on it can be used right now | Everything the model is given in this one request
Token | A word-piece on the invoice: you pay by the piece | The unit the model counts and bills. A word is roughly one to two tokens
Memory | A filing cabinet the consultant may open when needed | Notes the assistant looks up instead of carrying around
Vault (Obsidian) | A folder of one-page notes in plain text, linked together | A notes app where each note is a markdown file in a folder

The trade
A crowded desk costs more and buries the important page.
An empty desk means the consultant guesses.
So: put the right notes on the desk, at the right moment.


i
Context is the desk. Memory is the cabinet. You decide what goes where, and you pay for every sheet on the desk.

Terse mode: measure it, do not trust the headline

DEMO
17
MESA Term 2 | Advanced AI | S4: Plug It In
The claim | What was measured
'Cuts 65% of tokens' (the About line) | 33.2% fewer input tokens per session, from 54 Claude Code runs, all 18 checked answers correct (the vendor's own README)
Terse mode beats a plain request | A plain 'answer concisely' got most of the saving; the skill adds about 3% more at the median
It is free | The rules add about 1,160 input tokens to each request

Faculty demo, 4 minutes
Same question three times: normal, 'answer concisely', terse mode (if installed).
Count the output words each time.
Then ask: which would you let write to a founder?

Where it belongs
Developer notes and code review: fine.
Customer or founder messages: never. Clarity is the product.
Source: README of JuliusBrussee/caveman (a vendor's own measurements, reported as published). github.com/JuliusBrussee/caveman. Telemetry is on by default in its CLI.

Free-roaming or bounded? What suits a fund
22
MESA Term 2 | Advanced AI | S4: Plug It In
 | A free-roaming agent | A bounded agent (Dhruva)
Picture | An employee with a company card, no manager and a wide brief | An employee with a checklist, a limit and a manager who signs off
Memory | Keeps its own notes and updates them | Reads notes you wrote and approved
Skills | Can write itself new routines | Has the tools you gave it, no more
Audit | Hard: you must read what it decided to remember | Easy: fixed steps, a log, a human gate

--- slide 31
Reference: only plug in servers you trust
31
MESA Term 2 | Advanced AI | S4: Plug It In

Why
A server hands your assistant text.
Hidden instructions in that text are called prompt injection: a forged memo slipped into the in-tray.
A server that fetches web pages or emails can carry them.

What to do
Add only servers you wrote or trust.
Prefer read-only tools.
Make any tool that changes something ask a person first.
Read what the tool returns, not just what it claims.
Source: the Claude Code MCP documentation, code.claude.com/docs/en/mcp (the warning to verify trust before connecting a server).
