--- slide 3
Git is a filing system with a memory
3
MESA Term 2 | Advanced AI | S3: Ship It
Where | The office picture | The git word
1 Your desk | Papers you are editing right now | Working tree (your files)
2 The outbox tray | The papers you picked to file next | Staging area
3 The filing cabinet | Every past version, dated and signed | Repository (repo)
4 Head office copy | A shared drive everyone can see | Remote (GitHub)

The one idea
Git never forgets.
A commit is a dated snapshot you choose to file, with a note on it. A commit's receipt number is called a hash.

Think of it as
Version history in Google Docs, except you decide when to take each snapshot, and you must write a note saying what changed and why. Commit = file a snapshot. Push = send a copy to head office.


i
A commit is a dated snapshot with a note. The note is for the next person.

PAIR
5

Run two commands
git log --oneline
(a list of your snapshots, newest first)
Pick your partner's fix for Bug A, B or C.
git show <receipt number>
(opens one snapshot: the note and the change)

Say, in 60 seconds
What changed (name the lines).
Why (what problem it removed).
What else it affects: what happens to every other application's score?

Listener scores
Clear: I could repeat it.
Vague: I know the file, not the line.
Wrong: the effect is not what the change does.
A good answer | Example
Names the lines | 'score.py line 1 adds insufficient-data: 0. Line 6 now looks it up directly.'
States the effect on others | 'VaultNine drops from 10.0 to 0.8. Nothing else moves.'
Admits what it did not check | 'I did not test an unknown verdict value.'

Five questions to ask before you save anything
6
MESA Term 2 | Advanced AI | S3: Ship It
The question | The command | The office picture
What is on my desk? | git status | A quick look at the desk before filing
What exactly did I change? | git diff | The Track Changes view of papers not yet in the tray
What is in my tray? | git diff --staged | Reading the tray before it goes in the cabinet
What is in the cabinet? | git log --oneline | The index of every snapshot
What did that one snapshot do? | git show <receipt number> | Opening a single filed document

Read a change like Track Changes in Word
A line starting with + was added (green). A line starting with - was removed (red). A line with neither is just context. 'diff' is short for 'difference'.

--- slide 7
Predict: put everything in the tray, then file it

PREDICT
7
MESA Term 2 | Advanced AI | S3: Ship It

my-project/
  app.py
  .env           (GEMINI_API_KEY=abc123)
  reports/A01.json
  (no .gitignore)
$ git add . && git commit -m 'save'

What goes in the cabinet?
A  Only app.py.
B  app.py and reports/.
C  Everything, including .env.
D  Git refuses: it sees a key.

Two words
git add . means: put everything on my desk in the tray (the dot means everything).
An API key is the password to a paid service. Think of it as your company credit card number.

The fix
A .gitignore is a 'do not file' list. Put .env on it before the first snapshot.
If a key already got filed, it stays in the cabinet history. Treat it as stolen: cancel the card, get a new key.


i
git status is the last check before a secret leaves your desk.
--- slide 8
Reading a change: Track Changes for a project
8
MESA Term 2 | Advanced AI | S3: Ship It

config.py
  CRITERIA = [...]
- ADVANCE_AT = 7.0
+ ADVANCE_AT = 8.0
  MIN_EVIDENCE = 3

1 What changed
Which lines? How many?

2 Why
Is the reason in the note? If not, ask.

3 Trade-off
Who gains? Who loses? (A trade-off is what you give up to get something.)

4 Risk
What else did it touch that it should not have?

ADVANCE_AT in plain words
It is the pass mark. A startup scoring at or above it is advanced to a call with Dhruva. Raise the pass mark and fewer startups get through, which saves the analyst's time and risks missing a good one.


i
A change with no reason is a puzzle. A change with a reason and no trade-off is a sales pitch.

--- slide 12
Draft, merge, conflict, approval: five words from the office
12
MESA Term 2 | Advanced AI | S3: Ship It
Word | The office picture | What git does | Command
main | The signed master contract | The version everyone trusts and runs | (the default line)
Branch | A working draft copy of the contract | You change the draft. The signed one stays safe | git checkout -b <name>
Merge | Accepting the draft's changes into the master | Brings the draft's snapshots into main | git merge <branch>
Conflict | Two people redlined the same clause differently | Git stops and asks a human to decide | (appears during a merge)
Pull request (PR) | A change-request memo asking for sign-off | A page on GitHub where reviewers approve | (opened on github.com)
Revert | A reversing journal entry: you do not erase the old line, you post one that cancels it | A new snapshot that undoes an old one | git revert <receipt>


i
Never edit the signed master directly. Draft it, get it reviewed, then merge.

--- slide 15
Two redlines on one clause: how git shows a conflict
15
MESA Term 2 | Advanced AI | S3: Ship It

<<<<<<< HEAD
ADVANCE_AT = 8.0    # Ira: calls were thin last quarter
=======
ADVANCE_AT = 6.5    # analyst: missing seed-stage deals
>>>>>>> analyst-loosen
Marker | Means
<<<<<<< HEAD | Your version starts
======= | The line between them
>>>>>>> name | Their version ends

How to resolve
Keep one line, or write a new one.
Delete all three marker lines.
Run the code. Does it still give the expected output?

A merge note (example)
Merge analyst-loosen: pass mark 7.5

Why: 8.0 drops FactoryDesk (7.5). 6.5 adds nobody on this batch. 7.5 keeps today's shortlist. Ira to confirm.

The five steps: slip out, clerk works, answer back
20
MESA Term 2 | Advanced AI | S3: Ship It
Step | Who | The picture
1 | You (your app) | Hand the consultant the question and the job cards
2 | Model | Writes a slip: 'fetch application A03'
3 | Your code | The clerk does the job and gets a result
4 | Your code | Passes the result back through the slot
5 | Model | Writes the answer, or sends another slip

What this means
The consultant only knows what is on the job cards.
A vague label means the wrong slot.
A missing 'what if it jams' means a made-up answer.

Dhruva example
User: 'Should we take a call with FactoryDesk?' The model asks for the application, then the assessment, then the score. If one slot jams, what should it do? The job card has to say.


i
The job card is the only thing the model knows about your function.
--- slide 21
The job card: five parts, one page
21
MESA Term 2 | Advanced AI | S3: Ship It

name: get_application
description: Fetch one startup application
  by id. Use this first, before assessing.
inputs:
  app_id: text, required, example 'A03'
output:
  id, name, stage, sector, deck text
if it jams:
  NOT_FOUND     try again: no
     agent: ask once for a valid id, then
            hand to a human
  MISSING_FIELD try again: no
     agent: report the field, do not guess

What each part is
Name: a verb and a noun.
Description: the label on the slot. When to use it, when not to.
Inputs: the boxes on a form. Each has a type: text, whole number, yes/no. 'Required' means the form will not go through without it.
Output: what comes back.
If it jams: the error display, and what to do next.


i
The label decides which slot the consultant picks. Write it for the consultant.

--- slide 23
When a tool jams, the error screen tells the agent what to do
23
MESA Term 2 | Advanced AI | S3: Ship It
Code | Plain meaning | Try again? | The agent does | Seen in Dhruva
NOT_FOUND | No such record | No | Ask once for a valid id, then hand to a human | A99 is not in the file
MISSING_FIELD | A required box is empty | No | Report the field. Never guess it | S2 Lab 3: round_size_cr
TIMEOUT | No answer in time | Yes, once | Wait 2 seconds, retry once, then hand over | Live model call hangs
INVALID_VERDICT | A value the table does not know | No | Stop and hand over. Never score it as a point | S2 Bug A
AUTH | The key was refused | No | Say the tool is unavailable, then stop | Escalation service rejects key

Rules
'Try again?' is a busy phone line (yes, once) versus a wrong number (no).
Always return a code and a message. Never an empty answer or a made-up default: the agent cannot tell a jam from an answer.

Hand to a human
The formal word is escalate.
--- slide 24
Your two tools: one that looks, one that acts
24
MESA Term 2 | Advanced AI | S3: Ship It
Tool | What it does | Needs | Gives back | Changes anything?
get_application | Looks up one application | app_id | the fields and deck text | No. Read only
escalate_to_analyst | Sends a case to a human analyst | app_id, reason | ticket id, already_open | Yes. A ticket is created

Safe to call twice (the formal word is idempotent)
A lift button: press it twice and one lift comes. A pay button: press twice and you may be charged twice. A tool that changes something must behave like the lift button: if a ticket is already open, say so and do not open another.

Why these two
One looks, one acts. They teach the two kinds of tool.

Take-home
assess_application and score_application: same method, same check.

--- slide 36
Reference: undoing a change, and a key that got filed
36
MESA Term 2 | Advanced AI | S3: Ship It

Revert
A reversing journal entry: a new commit that cancels an earlier one.
The old line stays in the ledger.
Use it when a shipped change was wrong.

A key that got filed
Anyone who can read the repo can read the old snapshot.
Revert does not remove it.
Treat the key as stolen: cancel the card first (get a new key), then clean up.

What prevents it
A .gitignore before the first commit.
git status before every add.
A .env.example with names only.
Source: GitGuardian, State of Secrets Sprawl 2025 (a vendor report), for how often secrets are committed to public repositories.


i
Replace the key first. Cleaning the history comes second.
